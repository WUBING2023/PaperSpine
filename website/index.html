网页工作区

网页上能看到当前做到哪一步、还等你确认什么。真正的状态存在项目文件里，所以换会话、返修或转投都能接着做，不用从头再说一遍。

分工

Agent 负责推进流程；论文的贡献、动机、整图、作者声明和对外操作由你确认。网页只负责显示，不替代项目文件。

03 / 为什么用 PaperSpine5？

论文不是一次生成就完事。

真正难的不是多写一段文字，而是让主张、证据、配图、作者决定和交付要求在多轮修改里始终对得上。

01 / 文件为准

先看文件，再谈结论

配置、证据、配图决定、主稿和交付清单都有明确的存放位置。网页是操作窗口，记忆不只在网页里。

02 / 由你确认

对外的事，先问人

贡献、动机、整图、作者声明和投稿授权，不会因为 Agent 能做就默认你已经同意。

03 / 接着做

先恢复，再重做

五个阶段共用同一份项目状态。换会话、返修或转投时，不用重新猜之前定过什么。

04 / 从配置到投稿

从配置到投稿，
一步一步来。

每一步会产出什么、要等你确认什么、下一步接着用什么，这里都直接写清楚。

  1. 01

    CONFIGURE

    工作配置

    定义任务、材料、语言、引用、图件策略和交付偏好。

  2. 02

    ANCHOR

    论文定位

    贡献与动机由人确认，再约束章节主张和结果组织。

  3. 03

    FIGURE

    科研图件

    FigMirror 生成完整候选图，逐图审阅，每个采用或修改的决定都留档。

  4. 04

    CANONICAL

    主稿

    正文真正用上已确认的图件，最后再核对成稿画面和五项检查。

  5. 05

    PUBLICATION

    投稿循环

    在本地准备投稿材料、返修和转投计划；页面上没有自动投稿按钮。

10 / 常见问题

开始之前，
先把几个问题说清楚。

01PaperSpine5 只是一个 Skill 吗？

不只是。它是一套以本地文件为主的论文写作流程，通过 Skill 或插件接入宿主，并带一个五阶段网页界面。

02四个平台套件是四套产品吗？

不是。它们只是按平台分开的运行时包：Windows、Linux、Apple Silicon 和 Intel Mac；本版只提供完整套件，统一安装 paper-spine 入口。

03安装后会自动替我投稿吗？

不会。对外投稿、作者声明、费用和许可都需要你明确授权；“准备完成”也不等于“已经投出去”。

04社区星图代表安装量吗？

不代表。它只反映公开 GitHub Stargazer Atlas 的聚合分布，和安装量、活跃用户、产品能力是两回事。
