# PaperSpine

Work from the user's request, source files and saved decisions. Confirm only missing facts that affect the work, such as the material directory, permission to run a new study, or a choice the user reserved. Use chat for configuration, decisions and feedback. When installed, the PaperSpine Web plugin exposes `paper-spine-web:paper-spine-web` for the same paper.

Use the named paper folder and preserve the original materials. Reuse its current outputs on resume. If useful, keep one short working note with the goal, granted research scope, material locations, decisions, current source and next action. Apply explicit choices and delegated decisions. When using your judgment for a reversible editorial choice, say what you chose. Treat supplied results as the basis for claims. Start new experiments or data analysis only within the requested scope. Public literature and venue checks are part of writing unless the user requests offline work.

## Run the applicable stages

In the Skills Pack, load each applicable sibling directory's `SKILL.md` and execute its instructions with the same inputs and actual preceding outputs. Use native Skill invocation if available; reading and following the installed Skill is sufficient on hosts without nested invocation. In the single-Skill edition, use the corresponding bundled file in `references/stages/`. Read detailed methods only when applicable. Stage requests can start at the relevant existing files.

| Stage | Entry | What passes to the next stage |
| --- | --- | --- |
| Research and contribution | `paper-spine-study` | Research question, source-linked findings and evidence for the contribution |
| Followwriting | `paper-spine-followwriting` | Revised or newly drafted editable manuscript and real writing-example anchors |
| Scientific figures | `paper-spine-figures` | Evidence-linked, editable figures and matching captions |
| Review and revision | `paper-spine-review` | Located findings, supported corrections and their verification |
| Paper delivery | `paper-spine-deliver` | Requested editable files and inspected rendered outputs |

Drafting and figure work can inform each other. Compare motivation or figure choices in chat when a meaningful decision needs the user's input. Revise affected parts of the same paper after review. A focused correction uses the relevant stage and checks its affected outputs. A request for the full paper proceeds through delivery as far as real evidence and available tools allow.

Use actual inputs, quantities, citations and author facts. State consequential gaps in the handoff. Preserve original results and private files. For independent review, use a separate qualified reviewer when available and authorized; otherwise describe the check you performed and its limits. Deliver local file links and mention formats actually built.

For a managed install, enter through [the update instructions](../EDITION-MANAGEMENT.md) if the sibling manager is available. Check at most once per run, before opening stage instructions, and reread them after a successful update. Continue from the installed files when offline or when automatic updates are disabled.
